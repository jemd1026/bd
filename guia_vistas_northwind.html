Vistas en SQL Server

Aprende a crear, consultar, modificar y eliminar vistas SQL mediante casos prácticos de clientes, productos y pedidos de una empresa comercial.

01. Objetivos de aprendizaje

Al finalizar la sesión, el estudiante será capaz de:

  1. Explicar qué es una vista y en qué se diferencia de una tabla.
  2. Crear vistas simples y filtradas usando CREATE VIEW.
  3. Combinar tablas mediante JOIN dentro de una vista.
  4. Crear reportes resumidos con COUNT, SUM y GROUP BY.
  5. Consultar, modificar y eliminar vistas en SQL Server.
Requisito previo: haber instalado la base de datos Northwind y conocer SELECT, WHERE y conceptos básicos de JOIN.

Antes de comenzar: comprobar la base de datos

Verificación inicial Preparación
USE Northwind;
GO
SELECT TOP (5) CustomerID, CompanyName, Country
FROM dbo.Customers;

SELECT TOP (5) ProductID, ProductName, UnitPrice
FROM dbo.Products;
Si estas consultas devuelven filas, la base de datos está lista para la práctica.

02. ¿Qué es una vista?

Una vista (VIEW) es una consulta SQL guardada en la base de datos que se puede consultar como si fuera una tabla.

dbo.CustomersClientes
dbo.OrdersPedidos
dbo.EmployeesEmpleados
↓ SELECT / JOIN ↓
dbo.vw_ReportePedidosVista para consultar la información combinada
Idea central: una vista normal no guarda una segunda copia de los datos. Al consultarla, SQL Server obtiene los datos desde sus tablas de origen. Existen excepciones avanzadas, como las vistas indexadas.
TablaVista
Almacena registros físicamente.Habitualmente almacena la definición de una consulta.
Se crea con CREATE TABLE.Se crea con CREATE VIEW.
Puede consultarse con SELECT.También puede consultarse con SELECT.

¿Para qué sirven las vistas?

  • Simplificar: evitar repetir consultas con múltiples tablas.
  • Organizar: ofrecer conjuntos de datos útiles para reportes.
  • Controlar acceso: exponer columnas o filas seleccionadas junto con permisos adecuados.
  • Reutilizar: consultar una misma definición desde diferentes aplicaciones.

03. Sintaxis de CREATE VIEW

Estructura general
CREATE VIEW dbo.NombreVista
AS
SELECT columna1, columna2
FROM dbo.NombreTabla
WHERE condicion;
GO
ElementoSignificado
CREATE VIEWCrea una nueva vista.
dbo.NombreVistaEsquema y nombre de la vista.
AS SELECTDefine la consulta que representa la vista.
GOSepara lotes de instrucciones en SSMS.
Atención: CREATE VIEW debe ser la primera instrucción de su lote. Por eso se coloca GO después de USE Northwind y al terminar la vista. GO es un separador reconocido por SSMS, no una instrucción del motor SQL.

04. Ejemplos resueltos con Northwind

Ejecuta cada ejemplo por separado en una ventana de consultas de SSMS. Los nombres de las vistas tienen el prefijo vw_ para distinguirlas fácilmente.

Ejemplo 1. Vista simple: listado de clientes Básico
CREATE VIEW dbo.vw_Clientes
AS
SELECT CustomerID, CompanyName, City, Country
FROM dbo.Customers;
GO

SELECT * FROM dbo.vw_Clientes;
Aprendizaje: una vista se consulta mediante SELECT, igual que una tabla. Pregunta: ¿qué columnas contiene esta vista?
Ejemplo 2. Filtrar clientes de Alemania Básico
CREATE VIEW dbo.vw_ClientesAlemania
AS
SELECT CustomerID, CompanyName, City, Country
FROM dbo.Customers
WHERE Country = 'Germany';
GO

SELECT * FROM dbo.vw_ClientesAlemania;
Aprendizaje: la vista puede contener un filtro fijo. Reto oral: ¿cómo sería una vista de clientes de México?
Ejemplo 3. Vista de productos y categorías Intermedio
CREATE VIEW dbo.vw_ProductosCategorias
AS
SELECT
    p.ProductID,
    p.ProductName,
    c.CategoryName,
    p.UnitPrice,
    p.UnitsInStock
FROM dbo.Products AS p
INNER JOIN dbo.Categories AS c
    ON p.CategoryID = c.CategoryID;
GO

SELECT * FROM dbo.vw_ProductosCategorias;
Aprendizaje: los JOIN se guardan dentro de la vista para no reescribirlos cada vez.
Ejemplo 4. Vista con tres tablas: reporte de pedidos Intermedio
CREATE VIEW dbo.vw_ReportePedidos
AS
SELECT
    o.OrderID,
    o.OrderDate,
    c.CompanyName AS Cliente,
    e.FirstName + ' ' + e.LastName AS Empleado,
    o.Freight
FROM dbo.Orders AS o
INNER JOIN dbo.Customers AS c
    ON o.CustomerID = c.CustomerID
INNER JOIN dbo.Employees AS e
    ON o.EmployeeID = e.EmployeeID;
GO

SELECT TOP (10) *
FROM dbo.vw_ReportePedidos
ORDER BY OrderDate DESC, OrderID DESC;
Aprendizaje: el ORDER BY se aplica al consultar la vista. Una vista no garantiza el orden de las filas por sí sola.
Ejemplo 5. Contar pedidos por cliente Intermedio
CREATE VIEW dbo.vw_TotalPedidosCliente
AS
SELECT
    c.CustomerID,
    c.CompanyName,
    COUNT(o.OrderID) AS TotalPedidos
FROM dbo.Customers AS c
LEFT JOIN dbo.Orders AS o
    ON c.CustomerID = o.CustomerID
GROUP BY c.CustomerID, c.CompanyName;
GO

SELECT TOP (10) *
FROM dbo.vw_TotalPedidosCliente
ORDER BY TotalPedidos DESC;
Aprendizaje: COUNT resume información y LEFT JOIN también permite incluir clientes sin pedidos.
Ejemplo 6. Importe vendido por producto Intermedio
CREATE VIEW dbo.vw_VentasPorProducto
AS
SELECT
    p.ProductID,
    p.ProductName,
    SUM(od.UnitPrice * od.Quantity * (1 - od.Discount))
        AS ImporteVendido
FROM dbo.Products AS p
INNER JOIN dbo.[Order Details] AS od
    ON p.ProductID = od.ProductID
GROUP BY p.ProductID, p.ProductName;
GO

SELECT TOP (10) *
FROM dbo.vw_VentasPorProducto
ORDER BY ImporteVendido DESC;
Aprendizaje: el importe de cada línea considera precio, cantidad y descuento; el SUM agrupa las ventas por producto.

05. Consultar, modificar y eliminar vistas

A. Mostrar la definición con sp_helptext

EXEC sp_helptext 'dbo.vw_Clientes';
Muestra el texto de definición de la vista si el usuario tiene permiso y la definición no está oculta.

B. Modificar la vista con ALTER VIEW

ALTER VIEW dbo.vw_Clientes
AS
SELECT
    CustomerID,
    CompanyName,
    ContactName,
    City,
    Country,
    Phone
FROM dbo.Customers;
GO

SELECT * FROM dbo.vw_Clientes;
Ahora la vista también devuelve ContactName y Phone.

C. Crear o modificar en una sola instrucción

CREATE OR ALTER VIEW dbo.vw_Clientes
AS
SELECT CustomerID, CompanyName, City, Country
FROM dbo.Customers;
GO
Disponible desde SQL Server 2016 SP1. Útil para repetir scripts sin recibir el error “la vista ya existe”.

D. Eliminar una vista

DROP VIEW IF EXISTS dbo.vw_ClientesAlemania;
GO
Se elimina la vista, no los registros de dbo.Customers.

06. Acceso a datos y WITH ENCRYPTION

Vista que expone únicamente ciertos campos

Supongamos que un área solo necesita consultar nombres y países de clientes, pero no teléfonos ni direcciones:

CREATE VIEW dbo.vw_ClientesPublicos
AS
SELECT CustomerID, CompanyName, Country
FROM dbo.Customers;
GO

SELECT * FROM dbo.vw_ClientesPublicos;
Importante: ocultar columnas en una vista no impide el acceso directo a la tabla si el usuario ya tiene permisos sobre ella. El control real se implementa con permisos adecuados y una configuración de seguridad correcta.

Vista con definición ofuscada (WITH ENCRYPTION)

CREATE VIEW dbo.vw_ProductosPrecios
WITH ENCRYPTION
AS
SELECT ProductID, ProductName, UnitPrice
FROM dbo.Products;
GO

EXEC sp_helptext 'dbo.vw_ProductosPrecios';
La definición deja de mostrarse mediante sp_helptext. No cifra los datos ni sustituye permisos, copias de seguridad o controles de acceso. Guarda el script original antes de ejecutarlo.

Limitaciones fundamentales

  • Las vistas normales no aceptan parámetros; se filtran mediante una consulta externa (SELECT ... WHERE ...).
  • No se garantiza el orden de los registros sin ORDER BY en la consulta que lee la vista.
  • No todas las vistas son actualizables; aquellas que incluyen agregaciones o combinaciones complejas suelen tener restricciones.
  • Una vista puede basarse en otras vistas, pero demasiadas capas pueden dificultar el mantenimiento y rendimiento.

07. Taller práctico para estudiantes

Resuelve los casos con CREATE VIEW. Después de cada creación, demuestra que funciona mediante un SELECT sobre la vista.

Reto 1 — Clientes de Estados Unidos. Crea vw_ClientesUSA que muestre código, nombre, ciudad y país de los clientes cuyo país es USA.
Reto 2 — Productos costosos. Crea vw_ProductosCaros con nombre, precio y stock de productos cuyo precio sea mayor a 50.
Reto 3 — Inventario bajo. Crea vw_StockBajo que muestre productos con menos de 10 unidades en stock.
Reto 4 — Productos y proveedores. Une Products y Suppliers para mostrar producto, proveedor, país del proveedor y precio.
Reto 5 — Clientes y pedidos. Crea una vista que muestre número de pedido, fecha, empresa cliente y país.
Reto 6 — Productos por categoría. Crea una vista con nombre de categoría y cantidad de productos, usando COUNT.
Reto 7 — Precio promedio. Crea una vista que muestre el precio promedio de los productos por categoría, con AVG.
Reto 8 — Clientes frecuentes. Crea una vista que cuente pedidos por cliente y luego consulta solo los que tengan más de cinco pedidos.
Reto 9 — Administración. Modifica una vista para agregar una columna, consulta su definición y luego elimina una vista de prueba.

Preguntas de comprobación

¿Se pueden consultar las vistas con SELECT?

Sí. Por ejemplo: SELECT * FROM dbo.vw_Clientes;

¿La vista contiene una copia física de los datos?

Una vista normal no; contiene una definición de consulta. Las vistas indexadas son una excepción que se estudia en un nivel avanzado.

¿Qué ocurre si eliminamos una vista?

Se elimina el objeto vista, pero las tablas que utilizaba no se eliminan.

¿Las vistas aceptan parámetros como los procedimientos almacenados?

No directamente. Puedes aplicar filtros al consultarlas o utilizar procedimientos almacenados para recibir parámetros.
