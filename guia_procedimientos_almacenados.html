¿Qué es un procedimiento almacenado?

Un procedimiento almacenado es un conjunto de instrucciones SQL guardadas en una base de datos, que se puede ejecutar por su nombre. Puede recibir parámetros, realizar consultas y modificar registros.

Usuario
EXEC dbo.usp_ListarClientes→Procedimiento
Contiene SELECT→Northwind
Devuelve clientes
Comparación con las vistas: una vista se consulta con SELECT y representa una consulta; un procedimiento se invoca con EXEC y puede contener parámetros, condiciones y varias instrucciones.

Preparación

Abre SQL Server Management Studio (SSMS), conéctate y ejecuta:

SQL · Seleccionar Northwind 
USE Northwind;
GO

SELECT TOP (5) ProductID, ProductName, UnitPrice
FROM dbo.Products;

Si no aparece Northwind, primero instala la base de ejemplo. Cada CREATE PROCEDURE debe ejecutarse en su propio lote; por eso incluimos GO.

02 · Estructura

Sintaxis de un procedimiento almacenado

SQL · Estructura general 
CREATE PROCEDURE dbo.NombreProcedimiento
    @Parametro INT  -- opcional
AS
BEGIN
    -- Instrucciones SQL
END;
GO

EXEC dbo.NombreProcedimiento @Parametro = 1;
ElementoSignificado
CREATE PROCEDUREGuarda el procedimiento en la base de datos.
@ParametroDato que se recibe al ejecutar el procedimiento.
AS BEGIN ... ENDDelimita las instrucciones que ejecutará.
EXECInvoca el procedimiento.
GOSepara lotes en SSMS; no es una instrucción T-SQL.
Convención: usa usp_ como prefijo para tus procedimientos. Evita sp_ para procedimientos propios porque SQL Server lo utiliza para procedimientos del sistema.

04 · Parámetros de entrada

Procedimientos que reciben valores

Ejemplo 3 · Clientes por país

Situación: el vendedor quiere consultar los clientes de un país indicado al ejecutar el procedimiento.

SQL · Un parámetro 
CREATE PROCEDURE dbo.usp_ClientesPorPais
    @Pais NVARCHAR(50)
AS
BEGIN
    SELECT CustomerID, CompanyName, City, Country
    FROM dbo.Customers
    WHERE Country = @Pais;
END;
GO

EXEC dbo.usp_ClientesPorPais @Pais = N'Germany';
EXEC dbo.usp_ClientesPorPais @Pais = N'Mexico';
EXEC dbo.usp_ClientesPorPais @Pais = N'Brazil';
Observa: se crea una sola vez. Después puedes ejecutarlo con distintos países. @Pais es un parámetro de entrada, no una columna de la tabla.
Ejemplo 4 · Productos por rango de precios

Situación: necesitamos productos entre dos precios ingresados.

SQL · Dos parámetros 
CREATE PROCEDURE dbo.usp_ProductosPorPrecio
    @PrecioMinimo MONEY,
    @PrecioMaximo MONEY
AS
BEGIN
    SELECT ProductID, ProductName, UnitPrice
    FROM dbo.Products
    WHERE UnitPrice BETWEEN @PrecioMinimo AND @PrecioMaximo;
END;
GO

EXEC dbo.usp_ProductosPorPrecio
    @PrecioMinimo = 10,
    @PrecioMaximo = 50;
Reto oral: ¿Qué pasaría si enviamos el mínimo como 100 y el máximo como 10? ¿Cómo lo validarías?
05 · Lógica de decisión

Variables e IF...ELSE

Ejemplo 5 · Verificar stock

Situación: se desea comprobar si un producto está disponible, agotado o no existe.

SQL · DECLARE + IF + ELSE 
CREATE PROCEDURE dbo.usp_VerificarStock
    @IdProducto INT
AS
BEGIN
    DECLARE @Stock INT;

    SELECT @Stock = UnitsInStock
    FROM dbo.Products
    WHERE ProductID = @IdProducto;

    IF @Stock IS NULL
        PRINT 'Producto inexistente o sin stock informado';
    ELSE IF @Stock > 0
        PRINT 'Producto disponible';
    ELSE
        PRINT 'Producto agotado';
END;
GO

EXEC dbo.usp_VerificarStock @IdProducto = 1;
EXEC dbo.usp_VerificarStock @IdProducto = 99999;

Explica que PRINT aparece en la pestaña Messages / Mensajes de SSMS. En producción sería conveniente distinguir entre un producto inexistente y un valor NULL de inventario.

Ejemplo 6 · Validar mínimo y máximo
SQL · Validación sencilla 
CREATE PROCEDURE dbo.usp_ValidarRangoPrecios
    @Minimo MONEY,
    @Maximo MONEY
AS
BEGIN
    IF @Minimo > @Maximo
    BEGIN
        PRINT 'Error: el mínimo supera al máximo';
    END
    ELSE
    BEGIN
        SELECT ProductName, UnitPrice
        FROM dbo.Products
        WHERE UnitPrice BETWEEN @Minimo AND @Maximo;
    END
END;
GO

EXEC dbo.usp_ValidarRangoPrecios @Minimo = 100, @Maximo = 10;
EXEC dbo.usp_ValidarRangoPrecios @Minimo = 10, @Maximo = 100;

Situación: modificar el precio y stock de un producto existente.

CREATE PROCEDURE dbo.usp_ActualizarProducto

Ejemplo 9 · DELETE

Situación: eliminar un producto de prueba según su código.

SQL · Eliminar producto 
CREATE PROCEDURE dbo.usp_EliminarProducto
    @IdProducto INT
AS
BEGIN
    DELETE FROM dbo.ProductosPractica
    WHERE IdProducto = @IdProducto;
END;
GO

-- Comprueba antes qué registro eliminarás
SELECT * FROM dbo.ProductosPractica;
EXEC dbo.usp_EliminarProducto @IdProducto = 1;

Precaución: UPDATE y DELETE deben tener un WHERE adecuado. En aplicaciones reales agrega validación de parámetros, permisos y manejo de errores.

Complemento · Modelo de ventas

Productos, ventas y validaciones intermedias

Para practicar cambios reales sin tocar Northwind, usaremos una base separada. Ventas representa la cabecera (una venta) y DetalleVentas sus productos y cantidades. El detalle necesita esa cabecera para relacionarse correctamente.

Preparación: ejecuta el bloque inicial una vez en SSMS con permisos para crear bases de datos. Si no tienes esos permisos, pide que te creen TallerProcedimientos y comienza desde USE TallerProcedimientos. Los ejemplos trabajan únicamente en esa base.

1. Crear la base, las tablas y cargar 10 productos

SQL · Preparar el laboratorio 
IF DB_ID(N'TallerProcedimientos') IS NULL
    CREATE DATABASE TallerProcedimientos;
GO
USE TallerProcedimientos;
GO

IF OBJECT_ID(N'dbo.Productos', N'U') IS NULL
BEGIN
    CREATE TABLE dbo.Productos
    (
        ProductoId INT IDENTITY(1,1) CONSTRAINT PK_Productos PRIMARY KEY,
        Codigo VARCHAR(20) NOT NULL CONSTRAINT UQ_Productos_Codigo UNIQUE,
        Nombre NVARCHAR(100) NOT NULL,
        Precio DECIMAL(10,2) NOT NULL,
        Stock INT NOT NULL,
        Activo BIT NOT NULL CONSTRAINT DF_Productos_Activo DEFAULT (1),
        CONSTRAINT CK_Productos_Precio CHECK (Precio >= 0),
        CONSTRAINT CK_Productos_Stock CHECK (Stock >= 0)
    );
END;
GO

IF OBJECT_ID(N'dbo.Ventas', N'U') IS NULL
BEGIN
    CREATE TABLE dbo.Ventas
    (
        VentaId INT IDENTITY(1,1) CONSTRAINT PK_Ventas PRIMARY KEY,
        Fecha DATETIME2(0) NOT NULL CONSTRAINT DF_Ventas_Fecha DEFAULT (SYSDATETIME()),
        Estado VARCHAR(10) NOT NULL CONSTRAINT DF_Ventas_Estado DEFAULT ('ABIERTA'),
        CONSTRAINT CK_Ventas_Estado
            CHECK (Estado IN ('ABIERTA', 'CERRADA', 'ANULADA'))
    );
END;
GO

IF OBJECT_ID(N'dbo.DetalleVentas', N'U') IS NULL
BEGIN
    CREATE TABLE dbo.DetalleVentas
    (
        DetalleVentaId INT IDENTITY(1,1) CONSTRAINT PK_DetalleVentas PRIMARY KEY,
        VentaId INT NOT NULL,
        ProductoId INT NOT NULL,
        Cantidad INT NOT NULL,
        PrecioUnitario DECIMAL(10,2) NOT NULL,
        Total AS (Cantidad * PrecioUnitario) PERSISTED,
        CONSTRAINT FK_DetalleVentas_Ventas
            FOREIGN KEY (VentaId) REFERENCES dbo.Ventas(VentaId),
        CONSTRAINT FK_DetalleVentas_Productos
            FOREIGN KEY (ProductoId) REFERENCES dbo.Productos(ProductoId),
        CONSTRAINT CK_DetalleVentas_Cantidad CHECK (Cantidad > 0),
        CONSTRAINT CK_DetalleVentas_Precio CHECK (PrecioUnitario >= 0)
    );
END;
GO

2. Insertar un producto validando sus datos

El procedimiento rechaza código o nombre vacío, precio negativo y stock negativo; además, evita repetir el código.

SQL · Registrar producto 
CREATE OR ALTER PROCEDURE dbo.usp_RegistrarProducto
    @Codigo VARCHAR(20),
    @Nombre NVARCHAR(100),
    @Precio DECIMAL(10,2),
    @Stock INT
AS
BEGIN
    SET NOCOUNT ON;

    IF @Codigo IS NULL OR LEN(LTRIM(RTRIM(@Codigo))) = 0
        THROW 50001, 'El codigo es obligatorio.', 1;
    IF @Nombre IS NULL OR LEN(LTRIM(RTRIM(@Nombre))) = 0
        THROW 50002, 'El nombre es obligatorio.', 1;
    IF @Precio IS NULL OR @Precio < 0
        THROW 50003, 'El precio debe ser mayor o igual a cero.', 1;
    IF @Stock IS NULL OR @Stock < 0
        THROW 50004, 'El stock debe ser mayor o igual a cero.', 1;

    SET @Codigo = UPPER(LTRIM(RTRIM(@Codigo)));
    SET @Nombre = LTRIM(RTRIM(@Nombre));

    IF EXISTS (SELECT 1 FROM dbo.Productos WHERE Codigo = @Codigo)
        THROW 50005, 'Ya existe un producto con ese codigo.', 1;

    INSERT INTO dbo.Productos (Codigo, Nombre, Precio, Stock)
    VALUES (@Codigo, @Nombre, @Precio, @Stock);

    SELECT CONVERT(INT, SCOPE_IDENTITY()) AS ProductoId;
END;
GO

EXEC dbo.usp_RegistrarProducto
    @Codigo = 'TEC-011', @Nombre = N'Adaptador USB-C',
    @Precio = 15.00, @Stock = 20;
GO

3. Actualizar un producto existente

Se exige un identificador válido y se comprueban los nuevos valores antes del UPDATE. El filtro por clave primaria limita el cambio a un solo producto.

SQL · Actualizar nombre, precio y stock 
CREATE OR ALTER PROCEDURE dbo.usp_ActualizarProducto
    @ProductoId INT,
    @Nombre NVARCHAR(100),
    @Precio DECIMAL(10,2),
    @Stock INT
AS
BEGIN
    SET NOCOUNT ON;

    IF @ProductoId IS NULL OR @ProductoId <= 0
        THROW 50011, 'El identificador debe ser positivo.', 1;
    IF NOT EXISTS (SELECT 1 FROM dbo.Productos WHERE ProductoId = @ProductoId)
        THROW 50012, 'No existe el producto indicado.', 1;
    IF @Nombre IS NULL OR LEN(LTRIM(RTRIM(@Nombre))) = 0
        THROW 50013, 'El nombre es obligatorio.', 1;
    IF @Precio IS NULL OR @Precio < 0
        THROW 50014, 'El precio debe ser mayor o igual a cero.', 1;
    IF @Stock IS NULL OR @Stock < 0
        THROW 50015, 'El stock debe ser mayor o igual a cero.', 1;

    UPDATE dbo.Productos
    SET Nombre = LTRIM(RTRIM(@Nombre)),
        Precio = @Precio,
        Stock = @Stock
    WHERE ProductoId = @ProductoId;

    SELECT ProductoId, Codigo, Nombre, Precio, Stock
    FROM dbo.Productos
    WHERE ProductoId = @ProductoId;
END;
GO

EXEC dbo.usp_ActualizarProducto
    @ProductoId = 1, @Nombre = N'Teclado USB compacto',
    @Precio = 20.00, @Stock = 23;
GO

4. Registrar una venta con detalle y descontar inventario

Este procedimiento valida que la venta esté abierta, el producto exista y esté activo, y haya stock suficiente. La transacción garantiza que el detalle y el descuento de inventario se confirmen juntos o se reviertan juntos.

SQL · Insertar detalle de venta con transacción 
CREATE OR ALTER PROCEDURE dbo.usp_RegistrarDetalleVenta
    @VentaId INT,
    @ProductoId INT,
    @Cantidad INT
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;

    IF @VentaId IS NULL OR @VentaId <= 0
        THROW 50021, 'El identificador de venta debe ser positivo.', 1;
    IF @ProductoId IS NULL OR @ProductoId <= 0
        THROW 50022, 'El identificador de producto debe ser positivo.', 1;
    IF @Cantidad IS NULL OR @Cantidad <= 0
        THROW 50023, 'La cantidad debe ser mayor que cero.', 1;

    DECLARE @Precio DECIMAL(10,2);
    DECLARE @Stock INT;

    BEGIN TRY
        BEGIN TRANSACTION;

        IF NOT EXISTS
        (
            SELECT 1 FROM dbo.Ventas WITH (UPDLOCK, HOLDLOCK)
            WHERE VentaId = @VentaId AND Estado = 'ABIERTA'
        )
            THROW 50024, 'La venta no existe o no esta abierta.', 1;

        SELECT @Precio = Precio, @Stock = Stock
        FROM dbo.Productos WITH (UPDLOCK, HOLDLOCK)
        WHERE ProductoId = @ProductoId AND Activo = 1;

        IF @Precio IS NULL
            THROW 50025, 'El producto no existe o esta inactivo.', 1;
        IF @Stock < @Cantidad
            THROW 50026, 'Stock insuficiente para completar la venta.', 1;

        INSERT INTO dbo.DetalleVentas
            (VentaId, ProductoId, Cantidad, PrecioUnitario)
        VALUES (@VentaId, @ProductoId, @Cantidad, @Precio);

        UPDATE dbo.Productos
        SET Stock = Stock - @Cantidad
        WHERE ProductoId = @ProductoId;

        COMMIT TRANSACTION;

        SELECT DetalleVentaId, VentaId, ProductoId, Cantidad,
               PrecioUnitario, Total
        FROM dbo.DetalleVentas
        WHERE DetalleVentaId = CONVERT(INT, SCOPE_IDENTITY());
    END TRY
    BEGIN CATCH
        IF XACT_STATE() <> 0
            ROLLBACK TRANSACTION;
        THROW;
    END CATCH;
END;
GO

DECLARE @NuevaVentaId INT;
INSERT INTO dbo.Ventas DEFAULT VALUES;
SET @NuevaVentaId = CONVERT(INT, SCOPE_IDENTITY());

EXEC dbo.usp_RegistrarDetalleVenta
    @VentaId = @NuevaVentaId, @ProductoId = 2, @Cantidad = 3;

SELECT v.VentaId, v.Fecha, v.Estado, d.ProductoId, p.Nombre,
       d.Cantidad, d.PrecioUnitario, d.Total
FROM dbo.Ventas AS v
JOIN dbo.DetalleVentas AS d ON d.VentaId = v.VentaId
JOIN dbo.Productos AS p ON p.ProductoId = d.ProductoId
WHERE v.VentaId = @NuevaVentaId;
GO

5. Desactivar en lugar de borrar

Es preferible conservar el producto y su historial de ventas. Por eso, el borrado lógico cambia Activo; el procedimiento rechaza identificadores inexistentes.

SQL · Desactivar producto 
CREATE OR ALTER PROCEDURE dbo.usp_DesactivarProducto
    @ProductoId INT
AS
BEGIN
    SET NOCOUNT ON;

    IF @ProductoId IS NULL OR @ProductoId <= 0
        THROW 50031, 'El identificador debe ser positivo.', 1;
    IF NOT EXISTS (SELECT 1 FROM dbo.Productos WHERE ProductoId = @ProductoId)
        THROW 50032, 'No existe el producto indicado.', 1;

    UPDATE dbo.Productos
    SET Activo = 0
    WHERE ProductoId = @ProductoId AND Activo = 1;

    SELECT ProductoId, Codigo, Nombre, Activo
    FROM dbo.Productos
    WHERE ProductoId = @ProductoId;
END;
GO
Qué validamos: obligatoriedad y formato básico, rangos, identificadores existentes, unicidad, stock disponible, estado de la venta y relaciones entre tablas. THROW informa el error al cliente; las restricciones de tabla son una segunda barrera. Para un sistema real agrega autorización, auditoría y reglas de anulación/devolución.
Para practicar: prueba un código duplicado, precio negativo, producto inexistente, venta cerrada y cantidad superior al stock. Comprueba que cada intento produce un error claro y que no deja cambios parciales en DetalleVentas ni en Productos.
